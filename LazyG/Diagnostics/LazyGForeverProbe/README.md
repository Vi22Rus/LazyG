# LazyGForeverProbe — WoW Forever manual API audit (0.2.18-dev)

This is an isolated optional diagnostic addon, **not** installed by LazyG.exe. Its only purpose is to identify which Blizzard functions are present, return ordinary values, expose protected/unknown results, and which cast/aura events arrive in the exact user's Forever build. It does **not** bypass secret values, access their content, or drive rotations.

## Installation

Copy the entire `LazyGForeverProbe` folder (containing the TOC, CooldownAudit.lua, CooldownStateProbe.lua, CooldownWatch.lua, CooldownRgb.lua, SpellDiagnosticRgb.lua and LazyGForeverProbe.lua) to the **active** WoW Forever client `Interface/AddOns/` directory. Enable load-out-of-date addons if needed; `## Interface: 16001` is a research candidate from a Forever-aware addon, *not* confirmed against this specific build.

## Commands

- `/lgprobe api` — presence and selected C_Secrets result **types**.
- `/lgprobe spell 1130` — spell learned/usable/cooldown/charges and GCD probe; change spell ID for class/spec as appropriate.
- `/lgprobe cooldown 1130` (or `/lgprobe cd 1130`) — manual GCD/cooldown timing audit. Prints startTime, duration, modRate, isActive/isOnGCD availability and a **diagnostic-only estimated** remaining time when plain numeric inputs are readable; repeats the query for GCD SpellID 61304. Neither is evidence of combat readiness and values are never forwarded to RGB or XML. Test inside and outside combat after using a spell.\n- `/lgprobe target` — player and target health/power/GUID/cast **readability**, not their values.
- `/lgprobe cdstrip 13795` — enable separate LGC six-cell RGB state strip at top-left y=-76 (opt-in) for this SpellID; `/lgprobe cdstrip on` and `/lgprobe cdstrip off` toggle it. Then enable **LGC Cooldown RGB ON/OFF** in Windows Support while WoW is foreground. Both sides are required. The new six-cell packet reports spell isActive/isOnGCD and independent 29515 isActive/isOnGCD using 0/1/2/3/4 quality codes; no duration, no cast authorization. The existing LGD RGB strip and all RGB v2/v3/Curve packets are unchanged.\n- `/lgprobe cdwatch 1130` — one command starts **automatic 30-second recording**, plain spell/GCD flags at up to 20 samples/sec (50ms) and separate experimental cooldown widget at up to 5 samples/sec (200ms). Logs initial/final samples and **changes only**, with fractional seconds. The watch stops on its own; use `/lgprobe cdwatch status` or `/lgprobe cdwatch stop` if needed. Then `/reload` to persist SavedVariables. No combat action, no RGB changes, no clock timing demanded from the user.
- `/lgprobe cdcompare 1130` — experimental JustAC-inspired two-channel observation: plain `isActive` and `isOnGCD` flags plus a **separate, non-authoritative** hidden Cooldown widget test using `GetSpellCooldownDuration(spellID, true)`. It samples 1130, GCD candidate 61304 and alternative candidate 29515. `Shown/Hidden` is **only** a widget experiment, NOT proof of a cooldown, and never reaches RGB or the rotation engine.
- `/lgprobe aura player` or `/lgprobe aura target` — manually enumerate up to 20 aura slots and report whether spell ID, stacks, duration and instance-ID fields are readable. Absence or unsupported API is never reported as a confirmed missing aura.
- `/lgprobe events on` and `/lgprobe events off` — event hints for player and target, including only safe plain numeric SpellID when supplied, target epoch and no names/GUIDs. Events are capped (400 lines) and do not confirm specific aura presence.
- `/lgprobe rgb on` / `/lgprobe rgb off` — show/hide the six-cell LGD pixel strip (Hunter SpellID 1130 only in this test module), default OFF; Windows Support must also enable opt-in LGD capture. Never changes RGB v2/v3/Curve.\n- `/lgprobe show`, `/lgprobe clear` — last 20 entries or clear the log.

Enter `/reload` (or logout) to save `WTF/Account/<account>/SavedVariables/LazyGForeverProbe.lua` using the standard Blizzard SavedVariables mechanism. Upload the file after reviewing any contents you wish to withhold. Data include only time relative to login, API names, spell IDs supplied in commands, unit labels and status strings. The optional cooldown command deliberately records numeric cooldown timing estimates, startTime and duration if these API fields are plain/readable; review the SavedVariables content before sharing. Character names and GUID strings are not deliberately recorded. The client, not the addon, writes the SavedVariables file.

Test both in combat and out of combat, known/unknown spells, an ordinary cooldown, a charged spell, target swaps, and buffs/debuffs. `ProtectedOrError` is intentionally ambiguous, never evidence a secret has been decoded. `NumberReadable` means the *type* was readable, not that the number was stored or transmitted. In-game validation is pending.

The chat-attached test ZIP can differ from the live repository file while experiments evolve; prefer reviewing `main` before deploying code. No changes to the production RGB v2/v3 protocol or existing installation.

## LGD integration (experimental)

Open LazyG 0.2.9-dev > Support > **LGD SpellProbe ON/OFF**, then in game `/lgprobe rgb on`. The independent 6-cell strip is positioned at UI top-left, 65 UI units below the top edge. Keep the game visible and foregrounded for screen capture. Windows only accepts valid LGD packets when RGB v2 player/class identity is known; the source sequence must change and expires after 1.5 seconds. A frozen strip is Stale and cannot authorize a recommendation. The actual GCD time and cooldown remaining are Unknown. `/lgprobe rgb off` and Support toggle disable the experiment; no change to installed v2/v3/Curve modules. The captured status is shown in Support event logs; no automatic input is implemented. Game test pending.

## Cooldown audit in 0.2.14-dev

The manual command `/lgprobe cooldown 1130` writes two groups (`1130` and `61304`) to SavedVariables when `/reload` is used. Compare before-cast, just-after-cast and after-cooldown snapshots. `Protected`, `ApiMissing`, `Unknown` and `ProtectedOrError` are deliberate outcomes, not numbers. A numeric `remainingEstimateMs` is diagnostic and **not** a validated formula for secret or modified cooldown semantics; `modRate` is reported separately and not applied. No GCD or cooldown value is copied into GameState. CI now syntax-checks the entire diagnostic addon and runs a mocked Lua 5.1 cooldown-audit test. Until client results are observed and the wire protocol independently designed/tested, XML preview stays fail-closed.

## JustAC-inspired probe (0.2.15-dev)

`CooldownStateProbe.lua` is loaded before `SpellDiagnosticRgb.lua`. The latter keeps wire version 1 and the same six cells, but sources `CooldownActive` and `GcdActive` diagnostic bytes from the new guarded **plain boolean** probes. These values are `False/True/Unknown/Protected/ApiMissing`, are **not** time values and **never** turn a real spell or GCD into `Known 0 ms` in Windows GameState. `WidgetExperiment` tests an engine-driven Cooldown visual on a hidden frame, but the result is only printed by `/lgprobe cdcompare <SpellID>`; it is NOT copied into the RGB bytes. This intentionally isolates the unsupported `IsShown()` inference described by JustAC. Test before and after using a spell, during and outside combat, and after swapping targets. Do not assume either 61304 or 29515 is the correct Forever GCD until the actual client establishes that.

## Automatic 30-second capture (0.2.16-dev)

Enter `/lgprobe cdwatch 1130` once, close chat, and use an ability naturally during the next 30 seconds. The recorder samples spellID 1130 (or chosen integer ID), candidates 61304 and 29515, and a separately marked experimental visual widget. It records transitions and initial/final states with a `+0.000s` relative offset. The existing SavedVariables ring has capacity for 400 lines, so earlier records may roll off; a watch typically produces far fewer. Sample frequency is best-effort (`OnUpdate`), not a real-time guarantee. For a spell not known to your character, specify a valid known spell ID. After 30 seconds type `/reload` and inspect `WTF/Account/<account>/SavedVariables/LazyGForeverProbe.lua`; no character name or GUID is intentionally logged, but review all contents before sharing. Running the command does NOT need an active LazyG Windows program. No `DurationObject` widget finding is used to authorize the XML dispatcher. The current Windows EXE still displays 0.2.13-dev and has no rotation input from the recorder.

## 0.2.17-dev — distinct spell cooldown vs GCD and corrected widget setup

The real 0.2.16 Forever log showed seven 29515 `isActive=True` intervals aligned with 1130, while 61304 remained Unknown; that alone does not prove a spell-specific cooldown. With `/lgprobe cdwatch <SpellID>`, choose an ability that actually has an independent cooldown longer than the GCD (ideally 10–30 seconds). The capture prints `comparison` changes: `SpellActiveWhileGcdInactive` means *both plain booleans* are readable and show that the spell is active while 29515 is false. `SameBooleanState` is inconclusive, and `Unknown` never implies readiness. Do not use a synthetic SpellID unless it is known and actually castable for your character.

The native Cooldown widget diagnostic now uses a separate shown (not hidden) but alpha-zero 1×1 parent for each SpellID. This removes the previous hidden-parent confound and avoids reusing a single widget for different spells. **The widget result is still experimental:** `IsShown` describes visibility, not guaranteed cooldown activity. It is logged separately every ~200 ms, never transferred into RGB, GameState, or XML. These diagnostic changes do not affect Windows EXE (`0.2.13-dev` UI), base addon or key input. In WoW, enable the 0.2.17 probe, enter the command once, use the chosen ability naturally during the 30-second window, then `/reload` and inspect SavedVariables before sharing.

## LGC RGB diagnostic channel 0.2.18-dev (opt-in)

`CooldownRgb.lua` is its own 6 RGB cell LGC packet, not LGD. Signature ASCII `LGC`, wire version 1, sequence, reserved byte zero, 24-bit selected SpellID, four quality codes (spell isActive, spell isOnGCD, 29515 isActive, 29515 isOnGCD), two reserved bytes zero, fixed `A5` sentinel, 8-bit sum of bytes 1–15 and its complement. Byte codes: `0 Unknown`, `1 False`, `2 True`, `3 Protected`, `4 ApiMissing`. The Lua strip updates nominally every 100 ms when enabled; Windows polls the existing RGB snapshot about every 400ms. The six pixels sit to the left near y=76 and are read from the **same** foreground-WoW bitmap. It never converts `False` to `GcdRemainingMilliseconds=0` or to an XML cast permit. Invalid checksum/version, stale sequence, missing identity and unknown values fail closed. If you change a spell rank use `/lgprobe cdstrip <SpellID>` with its actual ID. No `IsShown()` outcomes are sent over this channel.

**Hands-free test**: `/lgprobe cdstrip 13795` once, Windows Support > `LGC Cooldown RGB ON/OFF`, switch back to WoW and cast naturally. To preserve a text diagnostic trace use `/lgprobe cdwatch 13795` separately, then `/reload`. On Windows, use `Copy all` for the LGC diagnostics, which include spell and GCD flags without needing to share screenshots. The Windows app must see the game foreground; opening LazyG can temporarily stop capture. RGB packets alone do not prove a cast is permitted.
