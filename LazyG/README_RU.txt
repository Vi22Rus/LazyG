LazyG 0.1.13-dev — ускоренное обновление диагностики RGB v2

Проверенная пользователем версия: 0.1.12-dev (RGB Bridge v2, четыре игровых сценария PASS).
Новая 0.1.13-dev требует проверки в WoW Forever. Ротации и клавиши пока не работают.

Что изменилось в 0.1.13-dev:
- В Overview Windows опрос RGB выполняется с интервалом 150 мс вместо 3 секунд.
- Захват и декодирование выполняются вне UI-потока; одновременно допускается только один захват, если прошлый ещё не завершился.
- RGB-пакет v2, Lua-аддон и мастер установки не менялись; установленный аддон 0.1.12-dev совместим с новой Windows-программой.
- 150 мс — интервал попыток опроса, а не измеренная задержка от события WoW до интерфейса. В игре не проверено.

Что реализовано ранее в RGB v2:
- RGB теперь ОДНА горизонтальная строка: 9 ячеек размером 4×4 UI, зазор 1 UI; весь блок 44×4 UI.
- Область у левого верхнего края окна WoW ищется автоматически. Никакого выделения мышью.
- Сохранены данные класса, расы, уровня, основной ветки талантов и очков.
- Начальный этап задачи №2: добавлены флаги существования цели, враждебности, жизни цели и режима боя игрока.
- Флаги событийные: PLAYER_TARGET_CHANGED, UNIT_FLAGS, UNIT_HEALTH, PLAYER_REGEN_DISABLED/ENABLED. Значения из защищённых/недоступных API не трактуются как уверенное «да».
- Windows декодирует и показывает флаги в Setup и Overview.
- Отдельный код HunterProfile.lua не изменялся. Существующие ротации, Healbot и Logitech не затронуты.

RGB Bridge v2:
Ячейка 4×4 UI, шаг 5 UI; девять ячеек в одном ряду.
[green][magenta][white][black][class,race,level][spec,points,version=2][flags,0,0][checksum,255-checksum,77][magenta]
flags: 1 = exists; 2 = attackable; 4 = alive; 8 = player combat.
checksum=(class*17+race*11+level*7+spec*19+points*3+version*13+flags*23)%256.

Проверка:
1. Скачать EXE артефактом GitHub Actions и запустить Setup.
2. Старую папку тестового аддона удалить/переименовать самостоятельно или выбрать новое имя установки. Setup не перезаписывает уже существующие папки.
3. Установленный аддон RGB v2 версии 0.1.12-dev менять не требуется. Если переустанавливали его файлы, выполните /reload.
4. В Setup убедиться в PASS / RGB protocol v2 / Hunter Tauren Level 29 Beast Mastery.
5. Менять цель: без цели / живая враждебная цель; входить и выходить из боя. Проверить оперативное обновление флагов без прежней задержки до 3 секунд.
6. Протестировать с привычными графическими настройками, без сброса; при ошибках сообщить UI Scale, режим окна и вывод теста.

Ограничения:
- Проверка реального отображения 4×4 при различных масштабах не выполнена; допускается откат к 0.1.11-dev.
- Булевы игровые значения, скрытые WoW Secret Values, могут стать недоступными; отрицательные флаги не всегда равны доказанному отсутствию условия.
- Не передаются HP%, ресурсы, способности, баффы, дебаффы, GCD и кулдауны. Следующие этапы задачи №2.
- Bridge требует видимого окна игры на переднем плане; EXE не читает память игры.
- GitHub Actions проверяет компиляцию и запуск EXE, но не WoW.
- Частота опроса 150 мс не гарантирует задержку <=150 мс: Lua-события, рендеринг, GDI-захват, планировщик и видимость окна влияют на время.

Команда создания одного EXE из папки Windows в PowerShell:
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
