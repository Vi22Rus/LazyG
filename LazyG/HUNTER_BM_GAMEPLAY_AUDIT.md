# Hunter Beast Mastery · WoW Forever · уровень 30
## Сквозной аудит XML ↔ наблюдаемое игровое исполнение (0.4.0-dev)

**Статус: DEV, НЕ ПОДТВЕРЖДЕНО В ИГРЕ.** Документ описывает уже реализованный журнал XML-диагностики и отдельно то, что ещё требуется до проверки фактического исполнения. Не считать CI проверкой живой ротации. Никаких нажатий клавиш XML-движок пока не выполняет.

### 1. Модель проверки

В каждом диагностическом срезе сохраняется:
- UTC-время, исходный RuleID / SpellID, статус каждого XML-условия, применённый порог Curve из 5%-ного диапазона, подтверждённость target/GCD, доказательства `SpellReady`, статус ранга;
- ожидаемая рекомендация **только если весь XML прошёл строгие условия**; иначе `Blocked` с причиной, и список условий всё равно остаётся в журнале;
- подтверждённое внешнее событие успешного применения заклинания — *отдельный канал*, не равный изменению LGD/LGC, отправленной клавише, сохранённому макросу или попытке выполнить действие;
- результат `Match` / `Mismatch` / `Unobservable` / `Blocked` и причину. `Mismatch` означает расхождение **наблюдаемого действия** и XML, а не доказательство ошибки LazyG: действие мог совершить игрок вручную.

Без достоверного CombatLogSuccess от **player** с правильной меткой времени и, при проверке target-specific действия, правильным `TargetEpoch` никакое действие не помечается `Match`. Только сравнительный контракт `HunterRotationAudit.Observe` и его тесты готовы; **живой канал CombatLogSuccess из Forever пока НЕ реализован**. Поэтому реальный отчёт текущей сборки закономерно покажет `Unobservable` / `Blocked`, а не выдуманные успешные атаки.

### 2. Подготовленный XML Hunter BM PvE

| Приоритет | Семейство / базовый SpellID | Условия | Настройка |
| --- | --- | --- | --- |
| 10 | Hunter's Mark / 1130 | свежий target, подтверждено отсутствие дебафа на **текущем** epoch; глобальные цели/GCD/SpellReady | `useHuntersMark` |
| 20 | Serpent Sting / 1978 | подтверждено отсутствие дебафа на текущем epoch; Curve мана >=30% (нижняя граница интервала) | `useSerpentSting`, `serpentManaMin` (шаг 5%) |

Это **не законченная PvE-ротация**. В частности, проверка автострельбы по обычному GCD не проверена; её нельзя без доказательств называть корректной. Не охвачены Aspect of the Hawk, питомец, Aimed Shot/Multi-Shot (классические и Forever shared cooldown), повторное применение метки по рангу и живость/диапазон цели. Нужны подтверждённые наблюдения и тесты на 30-м уровне.

### 3. Проверка рангов

`HunterSpellFamilies` хранит исследовательские семейства ID по Sonah/Hekili, а **выбирает конкретный ранг только на основании свежих Known(true) Learned и полного Known(true/false) перечисления всех кандидатов**. Отсутствующая информация о любом старшем ранге превращает статус в `RankSetUnverified`, не в догадку по уровню персонажа. Ни в коем случае нельзя считать базовый ID автоматически самым высоким рангом.

Базовые семейства: Метка `1130, 14323, 14324, 14325`; Укус `1978, 13549, 13550, 13551, 13552, 13553, 13554, 13555, 25295`; Чародейский `3044, 14281, 14282, 14283, 14284, 14285, 14286, 14287`; Автострельба `75`. Список является исследовательским, а не автоматическим ранг-резолвером текущего XML. ID/ранги требуют подтверждения в клиенте Forever.

### 4. Что можно проверить в игре уже этой dev-сборкой

1. Открыть LazyG → Hunter → Beast Mastery → PvE → **Hunter BM — открыть диагностику XML**.
2. В Support нажать **Start Hunter BM audit**. Затем переключиться в WoW Forever; сканер работает только при доступном окне игры.
3. С персонажем уровня 30 использовать Метку, Укус, Чародейский выстрел, автострельбу **вручную**, менять цель, дождаться дебафа, повторить при разных полосах маны (например 20–24, 25–29, 30–34). Проверить, что Lua Curve передаёт полосы, а не точные значения.
4. При необходимости включить отдельный **LazyGForeverProbe**: `/lgprobe diag 1130` и `/lgprobe events on`. С помощью `/lgprobe spell 1130`, `/lgprobe spell 1978`, `/lgprobe spell 3044` протестировать качество чтения Learned/Usable и конкретных рангов из книги. Включить Windows **Full RGB diagnostics ON/OFF**, если нужен LGD/LGC; проверка каждого ID делается последовательно, так как полосы LGD/LGC поддерживают один ID за раз. `/lgprobe aura target` проверяет доступность информации о дебафах, но не доказывает отсутствие эффекта.
5. В Support нажать **Stop Hunter audit**, затем **Save Hunter audit JSON**. Локальный файл `%LOCALAPPDATA%\LazyG\diagnostics\HunterBM-Audit-*.json` содержит до 200 безопасных срезов, без сырого RGB, имен, GUID, клавиш и снимков экрана. Никакого автоматического экспорта/загрузки нет.
6. Сохранить отдельный отчёт `Save RGB report`. После `/reload` (для сохранения стандартных Blizzard SavedVariables) можно отдельно изучить `LazyGForeverProbe.lua` с событием `UNIT_SPELLCAST_SUCCEEDED` и качеством `UnitAura`, **не пытаясь сопоставить GetTime() с UTC напрямую**: текущие два лога ещё не синхронизированы по шкале времени.

### 5. Как читать расхождения

- `Blocked`: XML отверг правило по конкретным отсутствующим/ложным условиям. В текущем Forever часто будет отсутствовать **подтверждение GCD, SpellReady либо TargetEpoch**. Это не означает, что WoW не выполнил ручной выстрел.
- `Unobservable`: XML смог бы выдать рекомендацию в полностью подтверждённом состоянии, но нет независимого подтверждения реального успешного применения.
- `Match`: возможно только при достоверном, отдельно проверенном `CombatLogSuccess` игрока, совместимом ранге и непротиворечивом временном/target окне.
- `Mismatch`: есть другое подтверждённое действие игрока в окне сравнения; нужно исключить ручной ввод, задержку, другой ранг, автоматическую атаку, смену цели, кулдаун и приоритет. Никогда автоматически не считать это поломкой LazyG.
- `Unknown` в трассе: значения защищены, устарели или не передаются; это **не ошибка расчёта** и **не разрешение произвести каст**.

### 6. Что обязательно сделать перед заявлением «полностью игровая ротация»

- Получить во Forever явные, не секретные `player CAST_SUCCEEDED` со свежим событием и связать их с монотонной временной шкалой Windows; проверить источник игрока, порядок, повторные события и смену цели. Если API не предоставляет эти данные, оставить `Unobservable`; скрытых обходов нет.
- Разобрать ранги изученных заклинаний, переходы при повышении уровня, одноимённые макросы и разные дебаф-ранги.
- Доказать детекцию Метки и Укуса по текущему target epoch; без этого невозможно безопасно утверждать «поддерживает дебаф».
- Подтвердить точные возможности GCD, кулдауна, аспекта, питомца, расстояния и swing timer; реализовать корректные приоритеты BM и offline/игровые регрессии.
- Когда будет безопасный сигнал и рабочий источник SRC: отдельно тестировать передачу команд через Windows (факт вызова), ввод в WoW (факт наблюдаемого успеха) и сравнение с XML; ни один этап не должен автоматически подразумевать другой.
- Провести полную проверку на реальном Hunter уровня 30 с отчётом и зафиксировать результат пользователя. Только после этого признать игровой сценарий работоспособным.
